| Q32 | What counts as a naming caption | RESOLVED (owner, 2026-10-10) | The vocabulary is an **instruction that binds**, not a mention. `business/reference_confirmation.py` reads a caption as a confirmation only when all four hold: an explicit save/link verb closes it — `saxla`, `yadda saxla` or `bağla`, where trailing marks that are not letters (`!`, `.`, an emoji) do not undo a closed phrase while `saxlama`, `saxlamaq`, `saxlanılsın` and `bağlama` keep letters after the verb and so do not close it; exactly one distinct product code appears after canonical normalization, so `KA-45` and `ka45` are one product while `KA45` and `KA46` are two; that code is *bound* to the picture, either by an Azerbaijani naming copula attached (`KA45-dir`, the clipped `KA45-dı`, the unhyphenated `KA45dır`) or standing as its own word (`KA45 dır`), or by the word naming the picture or the product immediately after it (`KA45 şəklini`, `KA45 məhsuluna`, `KA45 referans`, `KA45 üçün`) — matched as a prefix, because Azerbaijani folds case endings into the word, so `şəkli`, `şəkilini` and `şəklidir` all count; and nothing cancels the reading — a `deyil` anywhere denies it, and a question mark anywhere means the user was asking which product the picture shows. So each of the owner's five forms confirms (`Bu KA45-dir, yadda saxla`, `KA45 şəklini yadda saxla`, `Bu şəkli KA45 məhsuluna bağla`, `KA45 üçün referans şəkil kimi saxla`, `Bu KA45 məhsulunun şəklidir, yadda saxla`), while `Bu KA45-dir` and `KA45 şəklini göndərdim` carry no instruction, `Bu məhsul KA45, yadda saxla` and `KA45 anbarda var, yadda saxla` carry an instruction but no binding (a bare code in a sentence is a mention, and a mention is not consent — invariant 1), `Bu KA45-dir deyil, yadda saxla` is denied, `KA45 nədir, yadda saxla?` is a question, `KA45 şəklini yadda saxlama` and `Bu şəkli KA45 məhsuluna bağlama` negate the verb, and `Bu şəkli KA45 və KA46 üçün bağla` names two products — all of these write nothing. A digit is still required, because otherwise an ordinary word becomes an identity claim, and identity stays strict: `KA45-in şəklini yadda saxla` normalizes to `KA45IN`, which is a different code rather than a spelling of `KA45`, so the registry answers "no such product" and the parser guesses nothing. Photos only: a document caption carrying an instruction still reaches the service, which finds no picture in that message and refuses — nothing is inferred from a document. |
